# 内窥镜 Agentic RAG 完整设计总览（v0.3）

> 状态：设计定稿，待实施
> 本文是全系统总览：先讲思路，再讲三个部分（RAG 内部 agent / 大脑 / 自进化）和实施顺序。
> RAG 内部 agent 的数据构造参数与奖励细节见同目录 [RAG内部agent训练方案与数据构造_v0.3.md](./RAG内部agent训练方案与数据构造_v0.3.md)（下称“A 部分细则”）。
> 基座：Qwen3.5-4B（大脑 / RAG 内部 agent / 冻结生成器 / 图像检索视觉塔全链路统一）；文本检索 BGE-M3 冻结。

---

## 0. 一句话总结

大脑负责**提出疑惑点**和**复盘轨迹**，RAG 内部 agent 负责**把疑惑点搜成好证据**，生成器负责**作答和打分**。系统的经验分三层沉淀：

- 单题内的检索记忆（M+ / M-）
- 跨题通用的技能库（skill）
- 通过 OPD 内化到模型参数

每跑完一批题，大脑就复盘一次，把发现的冗余和可优化之处写成技能，验证有效后用 OPD 内化，系统由此一轮一轮自我进化。

## 1. 整体思路

### 1.1 系统要解决的四个问题
1. **旧数据有泄露**：检索会搜到题图自己，答案就在它的说明文字里 → 检索时排除题图和同一本书
2. **要学会怎么改写才能搜到好文段** → 同一疑惑点试多种问法，用生成器给结果打分，让 RAG 内部 agent 学习
3. **多轮改写要有方向** → 每一轮记下好文段和失败方向（M+ / M-），下一轮照着调整
4. **系统要能自己变好** → 大脑复盘完整轨迹，找出冗余步骤和可优化之处，沉淀为技能，再用 OPD 内化进模型

### 1.2 三个角色

| 角色 | 做什么 | 是否训练 |
|---|---|---|
| **大脑** | 答题模式：看题看图，提出疑惑点（初步改写），判断何时提交<br>复盘模式：分析完整轨迹，找冗余和优化点，写成技能 | 训练（第二部分 + 第三部分） |
| **RAG 内部 agent** | 把疑惑点改写成检索式 → 检索 → 留下好文段 → 记录经验 → 决定继续还是停止 | 训练（第一部分，最先做） |
| **生成器** | 看题、图和证据作答；给证据打分（answer-utility） | 冻结，作为打分标准 |

### 1.3 三层经验沉淀

| 层级 | 存什么 | 生命周期 | 例子 |
|---|---|---|---|
| 第一层：检索记忆 M+ / M- | 这道题里哪些文段有用、哪些问法失败了 | 单题内，题做完即清空 | 「消化道黏膜 内镜 图像」太宽泛，召回多为结肠 |
| 第二层：技能库 | 从大量轨迹里总结的通用做法 | 跨题长期保存，验证通过后才生效 | “器官识别题先问相邻器官的鉴别特征，检索式要带具体结构词” |
| 第三层：模型参数 | 已验证技能通过 OPD 内化进权重 | 永久，内化后该技能不再需要写进提示词 | 模型不看技能也会这样做 |

经验的流向：**单题经验 → 复盘总结成通用技能 → 内化成模型本能**。

### 1.4 答题：用一道题走一遍
```
题目：该内镜图像主要观察到的是哪个部位？ A食管 B胃 C十二指肠 D胆胰   答案：B
（题图及其所在的那本书已从检索库排除，模拟 EndoBench 的外部图像）
```
1. **大脑看图提出疑惑点**：看着像胃，也可能是十二指肠 → `rag_search(info_need="胃和十二指肠在内镜下的黏膜表现有什么区别")`
2. **RAG 内部 agent 第 1 次检索**：「消化道黏膜 内镜 图像」→ 8 条大多是结肠和病理切片，全部丢弃 → **记失败方向 M-**：太宽泛，召回多为结肠和病理 → 继续
3. **第 2 次检索**（参考失败记录，改搜具体特征）：「胃黏膜 腺管开口 内镜表现」→ 2 条描述胃黏膜特征 → 保留 → **记好文段 M+**：“胃窦黏膜腺管开口呈圆形小凹，支持 B” → 还缺十二指肠对照 → 继续
4. **第 3 次检索**：「十二指肠 绒毛 内镜表现」→ 1 条有用 → 保留 → 胃和十二指肠的特征都齐了 → **停止**
5. **返回大脑**：3 条好文段 + 诊断（“鉴别特征已找到”）+ 失败方向摘要 → 大脑 `submit_answer` → 生成器看图和 3 条文段作答

### 1.5 复盘：用一次自进化走一遍
我们在 v0.2.1 → v0.2.2 期间**手工**发现并修复过两个问题，它们正是分析器应该**自动**发现的那一类：

| 手工发现的问题 | 轨迹里的客观信号 | 分析器应该写出的技能 |
|---|---|---|
| 大脑用英文 query 搜中文语料，召回差 | 英文 query 那一步平均新增正类约 1 条，中文约 4–5 条 | “检索式用中文写，结合题干中文翻译和图像所见” |
| 最后一轮还在继续检索，导致预算耗尽未提交 | 末轮检索步新增证据对最终得分贡献≈0，且 2/10 题未提交 | “最后一轮直接提交，不再检索” |

自进化一轮的流程：
1. **跑题**：在训练题池上跑一批完整轨迹
2. **程序标注**：给每一步算客观指标，比如这一步新增了几条有用文段、去掉这一步最终得分会掉多少
3. **大脑复盘**：对比成功和失败的轨迹，找出冗余步骤和可优化之处，写成候选技能
4. **验证**：同一批验证题，带技能和不带技能各跑一遍，确实变好才让技能生效
5. **OPD 内化**：让“不看技能的模型”学习“看技能的模型”的行为，把技能变成本能
6. **回归测试通过 → 换上新模型 → 进入下一轮**

## 2. 旧数据问题诊断（摘要）

详见 A 部分细则第 1 节。
- **图像自命中泄露**：train3200 中 3200/3200 题的候选里有题图本身，2143 题排第一（score>0.999），带出写着答案的说明文字。agent 学到的是捷径，换到 EndoBench 外部图像就失效
- **只有图像检索路**：候选 100% 来自图像路、文本路 0 条，改写不影响检索结果，REWRITE 仅占 4.2%。根因是文本和图像候选按原始分数混排后取 top-12，而图像相似度（0.9–1.0）的量纲远高于文本分数，文本候选被全部挤掉；修正为两路按配额合并
- **题库问题**：实际用的是模板生成的 `mcq_image_v2_4000`（未验证，2 种题型，其中一种是 EndoBench 没有的元问题）

## 3. 第一部分：RAG 内部 agent（最先训练）

### 3.1 职责
输入大脑给的疑惑点，在工具内部最多检索 3 次（不消耗大脑预算）。每一步做四件事：
1. 写检索式
2. 从候选里留下好文段
3. 把经验写进检索记忆
4. 决定继续还是停止

返回给大脑：新增的好文段 + 一句诊断 + 失败方向摘要。

### 3.2 检索记忆 M+ / M-
- **M+ 好文段**：有用的文段 + 支持哪个选项 + 理由；同时就是最终交给生成器的证据集
- **M- 失败方向**：失败的检索式 + 失败原因（agent 写）+ 召回统计（程序算）
- 同一道题内所有轮次共享，包括大脑多次调用 rag_search 的情况
- agent 负责写，程序负责校验（编号必须真实存在、query 必须是实际执行过的）；解析失败时回落 v0.5 规则

### 3.3 数据构造（7 步，参数见 A 部分细则第 5 节）
1. **修检索环境**：排除题图和同一本书，打开文本检索路
2. **重建题库**：LLM 出题 + 独立模型盲答验证，题型对齐 EndoBench，约 3000 道训练题
3. **合成疑惑点**：教师模型看题看图，写 1–3 个疑惑点（这批数据同时是大脑的种子数据）
4. **每个疑惑点试 8 种问法**，每种都真实检索
5. **正负标注**：每条文段单独交给生成器，看它选对答案的把握是升还是降
6. **故意制造多轮**：
   - 失败路线：第 1 轮用最差问法 → 写 M- → 学“看到失败后往哪改”
   - 成功路线：第 1 轮用最好问法 → 再试一轮看增益 → 学“什么时候够了”
7. **组装四类样本**：首轮规划 / 筛选+继续 / 筛选+停止 / 查无结果

### 3.4 训练：SFT → GRPO（不做 DPO）
- **SFT**：照着标准答案学（8 种问法里最好的、只留正类、记忆写法、继续/停止）
- **GRPO**：同一道题让模型自己完整跑 8 遍，按结果打分，比平均好的做法被鼓励。打分项：
  - 最终证据对答题的帮助（主项）
  - 留下的文段里有用的占比
  - 记下的失败方向是否真的失败
  - 是否重复失败方向（扣分）
  - 检索次数（轻微扣分）

## 4. 第二部分：大脑 agent

大脑有两种工作模式，用的是同一个模型，换不同的提示词。

### 4.1 答题模式：提出疑惑点 + 判断提交

**动作空间**（不变，仍是两个动作）：
- `rag_search(info_need)`：说清楚“我哪里不明白”
- `submit_answer()`：证据够了就提交

**疑惑点的写法要求**：
- 围绕选项之间的鉴别点，比如“A 与 C 在 NBI 下的黏膜纹理区别”
- 结合图像所见，比如“图中隆起病变是黏膜层还是黏膜下来源”
- 具体、可检索，不直接写出答案
- 参考 RAG 内部 agent 返回的失败方向摘要，不提同一方向的疑惑点

**训练**：
- **SFT 数据**：
  - 第一部分第 3 步合成的疑惑点（教师模型写的）
  - 取 RAG 内部 agent 实际检索得分最高的那条疑惑点作为目标
  - 提交时机标签：最后一次检索的边际增益≈0 → 应该提交
- **GRPO（可选）**：同一题跑 8 遍完整答题流程。奖励 = 生成器最终答对与否 + 最终证据得分 − 调用次数成本
- 前提：RAG 内部 agent 训好并冻结后再训大脑，避免两边同时变动、分不清功劳

### 4.2 复盘模式：分析器

**任务**：读一批完整轨迹，回答三个问题：
1. 哪些步骤是冗余的
2. 哪些步骤可以做得更好
3. 能总结出什么通用做法

然后写成候选技能。

#### 4.2.1 先由程序标注，再交给分析器（关键设计）
分析器**不直接读原始轨迹**，读的是程序已标注好客观指标的轨迹。这样分析器的判断有数据支撑，不是凭感觉。

每一步自动计算的指标：

| 指标 | 含义 | 计算方式 |
|---|---|---|
| 新增正类数 | 这一步搜到几条有用文段 | 单文段 utility > τ+ |
| 边际增益 Δu | 这一步让最终证据得分涨了多少 | u(加入本步后的证据) − u(本步之前的证据) |
| 截断回放损失 | 去掉这一步，最终得分会掉多少 | 用“到上一步为止的证据”重新算 u，与最终 u 比较 |
| 重复度 | 这一步的问法和之前的有多像 | BGE-M3 余弦相似度 |
| 成本 | 检索次数、生成 token 数、耗时 | 运行日志 |

#### 4.2.2 冗余与可优化的客观定义
程序先按规则打标签，分析器在标签基础上找原因、总结规律：

| 类型 | 判定规则 | 例子 |
|---|---|---|
| 冗余步 | 新增正类 = 0 且截断回放损失 < 0.05 | 搜了一次什么都没多找到 |
| 重复步 | 和历史问法相似度 > 0.9 | 换汤不换药地再搜一次 |
| 过度检索 | 证据得分已达最终值的 95% 后仍继续检索 | v0.2.1 末轮还在搜 |
| 过早停止 | 停止后补一轮检索能让 u 提升 > ε | 证据不够就提交了 |
| 疑惑点偏题 | 该疑惑点的检索没有命中任何与选项相关的正类 | 问的东西和区分选项无关 |
| 问法低效 | 同类问题中，这种问法的平均新增正类明显低于其他问法 | 英文 query 对中文语料 |

#### 4.2.3 分析方式
- **按题型分组**：器官识别、病灶识别等分别分析，技能自然带上适用范围
- **成功 vs 失败对比**：同题型下高分轨迹与低分轨迹的步骤差异，是技能的主要来源
- **一次读一组**：每次输入 10–20 条同题型的标注轨迹摘要（不是全文），控制上下文长度

#### 4.2.4 分析器输出
```json
{
  "findings": [
    {"type": "问法低效", "scope": "器官识别题",
     "evidence": "23 条轨迹中，泛化问法（如「消化道黏膜 内镜」）平均新增正类 0.3 条；带具体结构词的问法平均 2.8 条",
     "suggestion": "检索式应包含具体解剖结构词"}
  ],
  "candidate_skills": [ {技能，格式见 5.1} ]
}
```

## 5. 第三部分：技能库与 OPD 自进化

### 5.1 技能长什么样
```
技能 #07  器官识别题：先问鉴别特征，不要泛搜
适用角色：大脑 + RAG 内部 agent
适用范围：题型 = 器官识别，且选项包含相邻器官（如胃 / 十二指肠）
做法：
  - 大脑：疑惑点写成“X 与 Y 在内镜下的鉴别特征”
  - RAG 内部 agent：检索式带具体结构词（腺管开口、绒毛、栅栏样血管）
反例：「消化道黏膜 内镜 图像」——召回多为结肠和病理切片，0 条有效
依据：23 条轨迹；采用该做法的平均得分 +0.52，未采用 +0.08
验证：验证集 A/B，正确率 +4%，平均检索次数 −0.6
状态：候选 → 已验证 → 生效中 → 已内化
```
技能存为结构化文件（`skills/skills.jsonl`），每条带版本号和来源轨迹 id，可追溯。

### 5.2 技能的生命周期
```
候选（分析器刚写出）
  → 验证（A/B 测试）
  → 生效中（写进对应角色的提示词，按题型匹配，最多注入 3 条）
  → 已内化（OPD 完成，模型不看技能也能做到 → 从提示词中移除）
  → 归档（保留记录，供论文分析和回溯）
未通过验证的 → 淘汰（保留记录，避免分析器反复提出同一条）
```

### 5.3 技能验证（进入 OPD 前的门槛）
分析器也可能总结错。**未经验证的技能不能内化**，否则错误经验会被写进模型。
- 验证题：从训练题池中留出的验证集（与挖掘技能用的轨迹不重叠），**EndoBench 严格不参与**
- 做法：同一批题、同一随机种子，带技能和不带技能各跑一遍，配对比较
- 通过条件（同时满足）：
  1. 适用题上，正确率或平均证据得分显著提升（配对检验 p < 0.05，或提升 ≥ 设定阈值）
  2. 不适用题上不下降（防止技能误伤其他题型）
  3. 平均成本（检索次数）不上升，或上升幅度在可接受范围内

### 5.4 OPD 内化：把技能变成本能
**思路**：同一个模型，“看着技能做题”的表现比“不看技能”更好。让“不看技能的模型”去学习“看着技能的模型”在每一步的选择，学会以后就不再需要技能提示。

- **老师**：当前模型 + 提示词中注入已验证技能（冻结）
- **学生**：当前模型，提示词中**不含技能**（训练对象）
- **在线（on-policy）**：由学生自己跑题、生成轨迹；老师对学生轨迹的**每一个 token** 给出自己的概率分布
- **损失**：学生与老师的逐 token 反向 KL 散度。学生在自己会走到的状态上，向“看了技能的自己”靠拢
- **为什么用在线蒸馏，而不是直接拿老师轨迹做 SFT**：学生在自己真实会遇到的情况上学习，没有“只见过老师走过的路”的分布偏差；而且信号是逐 token 的，比整条轨迹一个分数更密集
- **分角色内化**：大脑的技能在大脑的答题轨迹上内化，RAG 内部 agent 的技能在它的工具内轨迹上内化
- **内化验收**：在验证集上，学生（不看技能）的表现达到老师（看技能）的 90% 以上 → 该技能标记为“已内化”，从提示词中移除

### 5.5 自进化循环
```
第 k 轮：
  ① 跑题：当前模型在训练题池上跑一批完整轨迹（约 500 题）
  ② 标注：程序计算每一步的客观指标与冗余标签
  ③ 复盘：大脑（复盘模式）按题型分析，输出候选技能
  ④ 验证：A/B 测试，通过的技能进入“生效中”
  ⑤ 内化：OPD 把生效技能内化进模型
  ⑥ 回归：在固定回归集上测试，不退化才替换为新模型
  → 第 k+1 轮
```
- **停止条件**：连续两轮没有新技能通过验证，或验证集提升 < 1%
- **防退化**：固定回归集（各题型均衡）每轮必测，任一题型下降超过 2% 就回滚该轮
- **防泄露**：技能挖掘和验证只用训练题池，EndoBench 只做最终评测

### 5.6 分析器由谁来当
- 目标是**大脑自己当分析器**，这是“自进化”成立的前提
- 风险：4B 模型初期的归纳能力可能不足
- 做法：
  - 第 1 轮用教师模型（GPT）和大脑**各自**分析同一批轨迹，比较两者产出技能的验证通过率
  - 大脑的通过率可接受，就从第 2 轮起完全由大脑分析
  - 不可接受，就把“通过验证的 GPT 技能”作为范例，给大脑的复盘模式做少量 SFT，再切换
- 分析器自身也有客观反馈（它写的技能能否通过验证），可以作为后续改进复盘能力的训练信号

## 6. 评测与消融

### 6.1 指标
| 维度 | 指标 |
|---|---|
| 答案 | 生成器正确率；平均证据得分 u |
| 检索 | 每题有用文段召回数；文本候选占比 |
| 筛选 | 留下文段的有用率；有害文段误留率 |
| 记忆 | 失败方向标记准确率；重复失败方向的比例；第 2/3 轮的边际增益 |
| 效率 | 平均检索次数；冗余步占比；过度检索 / 过早停止比例 |
| 自进化 | 每轮通过验证的技能数；每轮验证集提升；内化后脱离技能提示的保持率 |

### 6.2 消融（论文贡献证据）
1. **泄露对照**：旧数据（自命中）训练 vs 新数据训练，在 EndoBench 上对比
2. **检索记忆**：完整 M+/M- vs 去掉 M- vs 去掉 M+ vs 都去掉；agent 写失败原因 vs 只记 query
3. **训练阶段**：零样本 vs SFT vs SFT+GRPO
4. **两级查询链**：大脑写疑惑点 + RAG agent 改写 vs 大脑直接写检索式（v0.2.2 方式）
5. **技能来源**：无技能 vs 技能写进提示词 vs OPD 内化（不看提示词）
6. **自进化轮数**：第 0 / 1 / 2 / 3 轮的性能曲线与冗余步占比曲线
7. **分析器**：GPT 分析 vs 大脑自身分析

## 9. 待定事项
1. **同书排除**：建议同书排除作主设定，只排除自身样本作对照
2. **题型范围**：建议对齐 EndoBench，参考原规划 4 类（解剖部位 35% / 病灶识别 30% / 操作识别 20% / 空间区域 15%）
3. **教师模型**：建议疑惑点合成与失败原因用 GPT，改写采样以 4B 自采样为主
4. **阈值**：τ+ / τ− / ε / ε_c 和冗余判定阈值，在 P3 / P9 小样上校准
5. **权重组织**：建议大脑与 RAG 内部 agent 用两套独立权重（同一 4B 底座分别训练，同卡加载约 16GB），避免互相干扰
6. **分析器**：第 1 轮 GPT 与大脑对照，再决定是否完全切换为大脑
