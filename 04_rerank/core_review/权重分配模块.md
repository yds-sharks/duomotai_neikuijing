# 权重分配模块

## 1. 模块定位

这部分不是向量检索模块，而是权重/标签分析模块。

当前核心脚本：

- [`multimodal_weight_service.py`](/mnt/data_1/yds/多模态/权重模块/multimodal_weight_service.py)

底层推理服务：

- [`semantic_density_service.py`](/mnt/data_1/yds/多模态/权重模块/semantic_density_service.py)

运行时配置：

- [`weight_module_runtime.yaml`](/mnt/data_1/yds/多模态/权重模块/weight_module_runtime.yaml)

## 2. 输入与输出

按你的描述，这个模块用于：

- 输入文本和图片
- 输出标签

但基于当前代码实现，现阶段公开接口实际上是：

- 主要输入：`query_text`
- 当前只支持文本侧分析

对应代码里有明确限制：

- `analyze(...)` 里只接收 `query_text`
- 若没有文本输入，会直接报错

所以现在可以这样理解：

- 业务定位上：这是“权重分配/标签判断模块”
- 当前落地实现上：先完成了文本侧分析接口

## 3. 当前输出内容

当前 `MultimodalWeightService.analyze(...)` 返回的是标签分析结果，不是检索结果。

输出主要包括：

- `density_level`
- `density_description`
- `image_dependency_level`
- `image_dependency_description`
- `model_outputs`

其中：

- `density_level`
  - 表示问题的语义密度等级
- `image_dependency_level`
  - 公开映射为 `R1 / R2 / R3`
  - 用来表示问题对图片的依赖程度

## 4. 当前配置

运行时配置文件：

- [`weight_module_runtime.yaml`](/mnt/data_1/yds/多模态/权重模块/weight_module_runtime.yaml)

当前配置项很少：

- `runtime.workspace_root = /mnt/data_1/yds/多模态/权重模块`
- `text_analysis.device = auto`

这意味着模型文件默认都从这个根目录下面找。

## 5. 当前加载的模型

这个模块没有 Milvus、没有向量库路径、也不直接做向量检索。

它加载的是 3 个本地 checkpoint：

- [`density_cls_v10_mengzi`](/mnt/data_1/yds/多模态/权重模块/checkpoints/density_cls_v10_mengzi)
- [`dependency_cls_v10_mengzi`](/mnt/data_1/yds/多模态/权重模块/checkpoints/dependency_cls_v10_mengzi)
- [`density_rank_v10_mengzi`](/mnt/data_1/yds/多模态/权重模块/checkpoints/density_rank_v10_mengzi)

这 3 个模型共同的底座模型是：

- `/mnt/data_1/yds/微调/models/mengzi-bert-base`

共同配置：

- `max_length = 96`
- `dropout = 0.1`

任务划分：

- `density_cls`
  - 5 分类
  - 输出语义密度等级
- `dependency_cls`
  - 3 分类
  - 输出图片依赖等级
- `density_rank`
  - 排序模型
  - 输出相对密度分数信号

## 6. 当前代码结论

这部分模块和检索模块需要明确分开：

- 它不负责召回文本或图片
- 它不依赖 `multimodal_vector_indexes.db`
- 它不连接 Milvus
- 它负责对输入内容做标签判断和权重分析

如果后面要把“输入文本和图片”真正都接起来，还需要继续看是否有未接入的图片侧接口，或者是否有上层服务在组合调用这个模块和检索模块。
