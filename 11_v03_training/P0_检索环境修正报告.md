## 1. 结论

100 题分层抽查（mcq_image_v2_4000/train.jsonl，两题型各 50，seed=0），三项验收全部通过：

| 验收项 | 阈值 | 实测 | 结果 |
|---|---|---|---|
| 自命中（题图自身出现在候选中） | = 0 | **0** | PASS |
| 同书命中（候选 doc_id 与题目同书） | = 0 | **0** | PASS |
| 文本候选占比 | > 30% | **68.1%** | PASS |

**旧环境对照（过滤前，即旧链路会看到的泄露水平）**：
- 100/100 题在过量召回 top-40 里出现题图自身（top1，score 0.996–1.002）——与旧 train3200 "3200/3200 自命中"完全一致
- 97/100 题存在同书候选

其余分布：文本路 100/100 题打满 8 条配额（文本路余量充足）；图像路 92 题满 4 条、8 题欠额（2/1/0 条，同书排除后不足，属预期）；平均每题候选 11.8 条；两类题型文本占比均匀（67.5% / 68.8%）。

## 2. 修正内容

旧环境两个结构性问题与修法（底层 `RetrievalRequest` 不支持排除参数，全部在应用层解决）：

| 问题 | 根因 | 修法 |
|---|---|---|
| 题图自命中泄露 | 检索库含题目来源样本，题图 caption 带着答案被召回 | 过量召回 k=40 → 按 `sample_id` / `image_path` 排除自身样本、按 `doc_id` 排除同书 → 再配额截断 |
| 文本路 0 条 | 文本(BGE-M3)与图像(视觉塔)分数量纲不同，旧代码全局混排取 top-12，0.9–1.0 的图像分占满候选 | 两路各自配额（默认文本 8 / 图像 4）后再合并 |

## 3. 实现清单

**新增 `11_v03_training/data_construction/`**：
- `leave_one_out_retriever.py`：`filter_leakage`（排除过滤）+ `LeaveOneOutRetriever`（过量召回→过滤→配额合并，检索器可注入便于单测）
- `p0_check_retrieval_env.py`：100 题抽查脚本（分层抽样、朴素题干+选项检索式、before/after 对照统计）
- `p0_probe_selfhit.py`：无排除对照实验（验证自命中存在性与过滤键匹配）

**harness 修改（`10_harness/`）**：
- `backends/rag_backend.py`：`FullRagPipeline` 重构为"检索 → 去泄露过滤 → 两路配额 → 证据筛选"，`search` 增加排除参数；`TopKFilter` 回落的混排问题在管线层一并解决（filter 拿到的已是配额后列表）；`MockRagPipeline` 兼容新签名
- `runtime/session.py`：`AgentSession` 新增 `exclude_sample_ids` / `exclude_doc_ids`
- `tools/rag_search.py`：调用时传入排除键（含题图路径）
- `brain/agent_brain.py`：`solve` 从题目 `gold_source`/`source` 填充排除键（库内来源题自动去泄露；EndoBench 外部图像键为空，行为不变）
- `harness_config.json`：retrieval 段新增 `overfetch_k=40`、`text_quota=8`、`image_quota=4`

## 4. 验证过程

1. Mock 单测：`filter_leakage` 键匹配与计数、`LeaveOneOutRetriever` 配额与排除（不占 GPU）
2. harness 全 Mock 冒烟（`run_smoke.py`）：SMOKE OK，链路未破坏
3. 3 题真实冒烟：PASS
4. 无排除对照（`p0_probe_selfhit.py`）：题图自身排图像路 top1，`SAME_IMG`+`SAME_SID` 全部匹配 → 过滤键格式正确
5. 100 题正式抽查：PASS（本报告第 1 节）

**过程中发现并修正的一个统计口径问题**：过滤顺序曾为"先同书后自命中"，而题图自身必属于同书，导致自命中统计被吸收进 `drop_same_book`（3 题冒烟 self=0 的假象）。已改为**先自命中后同书**（对最终保留集合无影响，只修正统计归属），修正后 100 题对照显示 100/100 自命中，与旧数据诊断完全吻合。
